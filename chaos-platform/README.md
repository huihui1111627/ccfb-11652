# 故障演练平台 · 在线挂号缴费系统

纯 Python 标准库实现(无需 pip install),在本机一个进程内拉起 **11 个服务实例**
组成的挂号系统同步调用链,每个实例前面挂一个**故障注入代理**,平台提供
**熔断 / 舱壁隔离 / 降级**组件和一个 Web **演练控制台**。

## 快速开始

```bash
cd chaos-platform

# 方式一:交互式 —— 启动集群 + 控制台,浏览器里操作
python3 run.py          # 打开 http://127.0.0.1:8600

# 方式二:对比实验 —— 同一演练计划在 关/开韧性 下各跑一次并打印对比
python3 demo.py         # 跑完后控制台继续运行,可去浏览器看报告
python3 demo.py --once  # 跑完即退出
```

## 系统拓扑

```
负载(挂号 8rps + 报告查询 4rps)
  -> gateway ──┬--> registration ──┬--> schedule --> doctor
               │                   ├--> patient
               │                   ├--> payment --> paychannel
               │                   └--> sms --> smsprovider-1 / smsprovider-2
               └--> inquiry --> patient
```

- 每个服务是**固定大小线程池 + 有界队列**的 HTTP 服务器(模拟 Tomcat),
  队列满直接 503 —— 用来真实复现"下游慢了,线程全卡住"的事故机理。
- 服务间调用全部经过目标实例前的**故障代理**,支持注入:延迟 / 返回错误 / 断开连接。
- 复现的事故剧本 `sms-slow`:运营商通道(smsprovider)延迟 50ms → 8s。

## 控制台(5 个页签)

| 页签 | 内容 |
|---|---|
| 服务拓扑 | 各服务线程池占用/错误率/p95 实时卡片,每条调用边的熔断器状态、舱壁、连接池、超时配置 |
| 演练计划 | 计划存为 JSON 模板,一键复跑(开/关韧性),历史演练勾选两次做对比 |
| 注入规则 | 手工增删规则,立即生效;支持按标记/实例/路径/百分比限制爆炸半径 |
| 稳态指标 | 演练中稳态检查实时结果;按历史延迟分位数给出每条调用边的超时建议,一键应用 |
| 演练报告 | 结论、客户端指标、线程池占用曲线、故障传播链、事件时间线 |

## 关键设计

1. **演练计划即模板**:`data/plans/*.json`,步骤按时间轴编排注入/恢复,
   可一键复跑;两次运行结果在报告页/计划页对比。
2. **稳态指标守护**:计划里声明(如 `client.error_rate < 0.3`),
   演练中每秒检查,连续 N 次偏离 → **自动中止并撤除全部故障**,再观察 10s 恢复。
3. **爆炸半径**:规则可限定 `match.tag`(请求头 `X-Chaos-Tag`,负载中 10% 流量带标)、
   `match.instance`、`match.percent`;内置 `sms-slow-tagged` 模板演示只打演练流量。
4. **熔断器**:滑动窗口统计错误率 + 慢调用比例,任一超阈值断开;
   冷却后进半开,放行 3 个探测请求,全成功才闭合。状态变化进事件时间线。
5. **超时建议**:`max(p99×1.5, p95+100ms, 200ms)` 向上取整到 100ms,按调用边给出。
6. **资源占用观测**:每 0.5s 采集各服务线程池活跃数/排队数/拒绝数、
   每个下游连接池占用,报告里画出故障沿调用链逐层扩散的曲线。
7. **降级**:非关键依赖(短信)配置 fallback —— 挂号照常成功,通知延迟补发;
   关键依赖(支付)无降级,快速失败,报告会指出"没守住的地方"。

## 对比实验结论(demo.py 实测)

同一 `sms-slow` 计划:

- **关韧性**:sms 线程占满 → registration 20/20 → gateway 30/30 → 全站 503/超时,
  稳态失守自动中止,故障扩散到 gateway/registration/sms/inquiry。
- **开韧性**:registration→sms 熔断器秒级断开,舱壁把短信调用限制在 3 个并发,
  fallback 降级为"短信延迟补发",客户端错误率≈0,p95 回到 200ms 级,
  故障被限制在注入点,报告查询(inquiry)全程无感。

## 目录结构

```
chaos/
  core.py        有界线程池服务器、连接池客户端、指标窗口
  resilience.py  熔断器、舱壁
  service.py     服务框架、下游调用封装(熔断/隔离/降级/超时)
  hospital.py    挂号系统拓扑与业务逻辑
  proxy.py       故障注入代理与规则匹配
  engine.py      采集器、负载发生、演练引擎、计划/运行存储
  report.py      报告汇总与对比
  advisor.py     超时建议
  console.py     控制台 API
  static/        控制台前端
run.py           交互式启动
demo.py          开/关韧性对比实验
```
